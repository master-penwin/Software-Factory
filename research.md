Existing methods for taking a product from idea to published, collected as raw material for our workflow.

## Ideas worth testing
1. Fix the time, flex the scope. (Shape Up, game jams)
2. Write it on one page before building. (README-driven, Shape Up)
3. Test the riskiest assumption first, cheaply. (Lean Startup, fake door)
4. The AI grills you, one question at a time, each with its recommended answer. (Matt Pocock, Harper Reed)
5. Plans, to-dos and state live in plain files, so any fresh session can resume. (Mario Zechner, Harper Reed)
6. Minimal tooling: a few scripts plus a short README beat heavy integrations. (Mario Zechner)
7. Build thin end-to-end slices, not layers. (Matt Pocock)
8. Keep each task small enough for a fresh context; restart instead of compacting. (Pocock, Zechner)
9. Close the loop: automatic checks after every change, plus a separate reviewer. (IndyDevDan)
10. One spec, several agents in parallel, each a different direction; pick one. (IndyDevDan, v0)
11. Review plans, not code, and cap output to what you can actually review. (plan mode, Zechner)
12. A ship date beats a plan; one active project at a time. (Pieter Levels, Kanban)

## Common failures
- Process becomes the work.
- Plans and specs drift from what's built and mislead later sessions.
- Small agent errors pile up unseen; you become the review bottleneck.
